# Switch, remove or add template features (Expo)

`AGENT_START.md` in the builder root is the authority; `_expo/docs/FEATURES.md` lists exactly what each
feature contains and what each command changes. Read it before acting.

## Decide the operation
- **Off/on** (soft): the user wants the feature inactive for now, or has no keys yet. Code stays.
- **Remove** (hard): the user does not want the feature's code or native packages in the app.
- **Add**: put back a removed feature, or add `funnel` (upstream 28-step onboarding and full paywall).
If the user did not say which, explain the difference in one or two sentences and ask.

## Steps
1. `bash start.sh expo feature status <app>` and `git -C <app> status --short`. Uncommitted work in the
   app: tell the user and suggest committing first.
2. Run the command from the builder root:
   - `bash start.sh expo feature off|on <id> <app>` (ids with a switch: auth, payments, analytics, notifications)
   - `bash start.sh expo feature remove <id> <app>`
   - `bash start.sh expo feature add <id> <app>`
3. If the command refuses because files changed, show the listed files to the user. Do not pass
   `--force` unless the user agrees after seeing them; `--force` overwrites their edits.
4. In the app: `bash start.sh verify`.
5. For features with native code (auth, payments, analytics, notifications, local-db, device-kit,
   ota-updates, funnel), rebuild the development client before testing on a device.
6. After `add funnel`: tell the user the onboarding questions, copy and graphs are demo content to
   replace (`src/features/onboarding`, `src/constants/content.ts`), and that the migration
   `supabase/migrations/0002_onboarding_funnel.sql` must be applied to their Supabase project.
7. Commit the app including `.mobile-builder/` only if the user asked for commits.

## Rules
- Never delete feature files by hand; other files import them. The tool swaps in stubs with the same exports.
- `funnel` needs auth, payments, analytics and notifications present.
- Removing a feature does not remove its dashboards or server data (Supabase project, RevenueCat
  products, PostHog project); list those for the user if they want them gone.

## Done when
`verify` passes in the app, `feature status` shows the requested state, and the report lists what was
removed or added and what was not tested on a device.
